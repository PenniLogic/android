# Android scaffold

Reproducible Gradle/Kotlin scaffold for the PenniLogic Android client (android#1, plan item
T-SCA-AND-01) plus the Android 16 / API 36 platform baseline (android#57, plan item T-AND-07). It
contains one application module with an entry activity, environment-only configuration loading, a
debug/release variant matrix, unit tests, lint and formatting gates and a coverage report, and the
reusable platform primitives described under "Android 16 platform baseline". It contains no product
navigation, storage, permission or network journey.

`README.md`, `AGENTS.md` and the workflows under `.github/` are generated by
`PenniLogic/infra/governance`; this file documents what the scaffold itself provides.

Required on the machine: a JDK 21 on `PATH` or `JAVA_HOME`, and an Android SDK reachable through
`ANDROID_HOME` (or `local.properties`, which is never committed) with `platforms;android-36`,
`build-tools;36.0.0` and `platform-tools`. Licenses must already be accepted with the SDK
manager; the build never accepts them on your behalf. Every other dependency is downloaded by
Gradle from Google Maven and Maven Central at the exact versions in the catalogue; Robolectric
additionally downloads its SDK runtime jars (36 by default; 31, 33 and 35 for the API-level matrix
test) from Maven Central into `~/.m2` on first use.

## Commands

Run from the repository root of a clean clone. No other setup step is required.

| Purpose | Command |
| --- | --- |
| Assemble both variants, unit tests for both variants, lint (debug variant), formatting | `./gradlew build` |
| Debug and release APKs | `./gradlew assembleDebug assembleRelease` |
| Unit tests (both variants; JVM and Robolectric on the SDK 36 runtime) | `./gradlew testDebugUnitTest testReleaseUnitTest` |
| Android lint on both variants (warnings are errors) | `./gradlew lintDebug lintRelease` |
| Formatting check / fix | `./gradlew spotlessCheck` / `./gradlew spotlessApply` |
| Unit-test coverage report (JaCoCo) | `./gradlew createDebugUnitTestCoverageReport` |
| Install the debug APK on the connected device or emulator | `./gradlew installDebug` |
| Instrumented tests on the connected API 36 emulator (local evidence; CI has no emulator) | `./gradlew connectedDebugAndroidTest` |
| Sideloaded-QA prerequisite check on the connected device (read-only) | `python scripts/qa_sideload_prerequisites.py` |
| Gates with pipeline metrics | `python scripts/quality_gates.py all` |
| Gate self-test on planted defects | `python scripts/quality_gates.py self-test` |
| Script unit tests | `python -m unittest discover -s scripts/tests -p "test_*.py"` |

On Windows use `gradlew.bat` in place of `./gradlew`. `gradle.properties` sets
`android.onlyEnableUnitTestForTheTestedBuildType=false` so the release variant also has a unit
test task; without it AGP 9 creates unit tests for the debug variant only. Unit tests run with the
`--add-opens` JVM flags Robolectric documents for Java 17+, and `app/build.gradle.kts` hands each
variant's merged manifest to its unit tests as the `pennilogic.mergedManifest` system property so
`TargetConformanceTest` inspects exactly what AGP packaged.

Lint runs with `warningsAsErrors` and no baseline file. Three checks are disabled deliberately, each
with its reason in `app/build.gradle.kts`: `OldTargetApi` (targetSdk is pinned to the Play-required
API 36 baseline and raising it is a reviewed decision guarded by `TargetConformanceTest`) and the
release-calendar checks `AndroidGradlePluginVersion` and `GradleDependency`, which would otherwise
fail a pinned build the day a newer Gradle or dependency is published.

Reports: unit tests `app/build/reports/tests/`, JUnit XML `app/build/test-results/`, lint
`app/build/reports/lint-results-<variant>.{xml,html,txt,sarif}`, coverage
`app/build/reports/coverage/test/debug/`, metrics `build/quality-metrics.json`.

`scripts/quality_gates.py` runs the Gradle tasks above, then records build duration, unit test
counts (tests, failures, errors, skipped) and lint issue counts by severity in
`build/quality-metrics.json`; when `GITHUB_STEP_SUMMARY` is set it also appends a Markdown
table to the job summary. `self-test` plants a failing unit test, a formatting violation and an
unused resource one at a time, asserts that the matching gate exits non-zero (and that the
failing test is counted as a failure, not skipped), removes each planted file and finally runs
the gates again to prove they pass without the defects.

## Build configuration keys

Configuration is read from the process environment at build time and baked into `BuildConfig`.
Nothing is read from files, and no value is committed. At run time
`com.pennilogic.android.config.ConfigurationLoader` validates the baked values and the entry
screen shows either "Configuration loaded." or the list of `KEY:kind` problems; an invalid
configuration is a displayed state, not a crash.

| Environment variable | Type | Required | Debug default | Release default | Validation |
| --- | --- | --- | --- | --- | --- |
| `PENNILOGIC_ENVIRONMENT` | string | yes | `development` | none (reported missing) | one of `development`, `staging`, `production` |
| `PENNILOGIC_API_BASE_URL` | string | yes | `https://api.dev.pennilogic.invalid` | none (reported missing) | absolute `https` URL with a host; no user info, query or fragment |
| `PENNILOGIC_BUILD_LABEL` | string | no | `local` | `local` | printable ASCII, at most 64 characters |

Blank values count as unset. Problems are reported by key and kind (`missing` or `invalid`) and
never include the offending value.

### Release signing

| Environment variable | Required for a signed release |
| --- | --- |
| `PENNILOGIC_RELEASE_KEYSTORE_PATH` | yes |
| `PENNILOGIC_RELEASE_KEYSTORE_PASSWORD` | yes |
| `PENNILOGIC_RELEASE_KEY_ALIAS` | yes |
| `PENNILOGIC_RELEASE_KEY_PASSWORD` | yes |

When none of the four variables is set, `assembleRelease` produces an **unsigned** APK
(`app-release-unsigned.apk`). When all four are set, the release variant is signed with that
keystore. A partial set fails configuration with a message naming the missing variables. The debug
variant is signed with the debug keystore that the Android Gradle plugin generates locally in
`~/.android/`; no keystore, password or token exists in this repository, and
`scripts/check_repository.py` rejects `*.keystore`, `*.p12` and `*.pfx` files in every commit.

## Build variants

| Variant | Application ID | Version name | Minified | Signing |
| --- | --- | --- | --- | --- |
| `debug` | `com.pennilogic.android.debug` | `0.1.0-debug` | no | local debug keystore |
| `release` | `com.pennilogic.android` | `0.1.0` | yes (R8, resource shrinking) | environment-provided or unsigned |

Both variants disable cleartext traffic (`android:usesCleartextTraffic="false"` plus a network
security configuration whose base config forbids cleartext with no domain exceptions), exclude
all application data from backup and device transfer (`data_extraction_rules.xml` for Android 12+
and `backup_rules.xml` for older releases), and request no permissions in the source manifest.
`ManifestContractTest` parses the **source** manifest (`app/src/main/AndroidManifest.xml`) and its
XML resources; it fails if any of these declarations changes, and it asserts that the source
declares exactly one exported activity and no service, receiver or provider. It does not inspect
the merged manifest inside the APK.

### Merged manifest per variant

Library manifests merge into the built APK. Verified with
`aapt2 dump xmltree --file AndroidManifest.xml <apk>` on the scaffold's own builds:

| Component (merged manifest) | Origin | `debug` | `release` | Exported | Guard |
| --- | --- | --- | --- | --- | --- |
| `com.pennilogic.android.MainActivity` | source manifest | yes | yes | yes | launcher intent filter only |
| `androidx.compose.ui.tooling.PreviewActivity` | `debugImplementation(androidx.compose.ui:ui-tooling)` | yes | **no** | yes | debug-only; Android Studio's preview/"run composable" host, no product code path |
| `androidx.activity.ComponentActivity` | `debugImplementation(androidx.compose.ui:ui-test-manifest)` | yes | **no** | yes | debug-only; empty host activity for the synthetic-composition tests (Robolectric `RootSurfaceTest`, `PenniLogicBackHandlerTest` and the instrumented back and large-screen tests); it sets no content of its own |
| `androidx.profileinstaller.ProfileInstallReceiver` | `androidx.profileinstaller` (transitive from Compose/Activity) | yes | yes | yes | `android.permission.DUMP` (signature/privileged; only shell/tooling can send) |
| `androidx.startup.InitializationProvider` | `androidx.startup` (transitive) | yes | yes | **no** | authority `<applicationId>.androidx-startup` |
| `<applicationId>.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | `androidx.core` (apps targeting API 33+) | yes | yes | n/a | signature permission declared and used by the app itself; not a runtime permission |

`PreviewActivity` and the test-manifest `ComponentActivity` are kept in the debug variant on
purpose: the first is what Android Studio uses to run `@Preview` composables on a device, the second
hosts the synthetic compositions of the platform tests; both are absent from release, and stripping
them would mean editing the build files or adding a manifest override for no security gain in a debug
build. If a later ticket wants a debug manifest without them, the change is a `tools:node="remove"`
entry in a `src/debug/AndroidManifest.xml`. Any future component that appears in the merged manifest
must be added to this table. The source manifest now also declares
`android:enableOnBackInvokedCallback="true"` on `<application>` (predictive back; see the platform
baseline below); it is the only attribute added by android#57.

## Continuous integration check identifiers

The required native GitHub check is the job named `CI` in `.github/workflows/ci.yml`. That
workflow is generated from `PenniLogic/infra/governance`; it installs JDK 21 and the Android SDK
packages above, verifies the Gradle wrapper checksum and runs `python scripts/check_repository.py`,
the four quality gates (`build`, `test`, `lint`, `coverage`), the gate `self-test` and the script
unit tests. Every JVM and Robolectric test in `app/src/test` is therefore CI-enforced for both
variants. CI has no emulator: the instrumented tests under `app/src/androidTest` are local evidence
run with `./gradlew connectedDebugAndroidTest` on the API 36 emulator and attached to the pull
request, never claimed as CI results.

## Android 16 platform baseline (android#57)

Package `com.pennilogic.android.platform`. The primitives below are what feature tickets consume;
they carry no product UI and no private Android-version workaround. The behaviour record for T-QA-12
and the QA documents live in `docs/platform/`:

| Document | Content | Kept honest by |
| --- | --- | --- |
| `docs/platform/android-behavior-matrix.{json,md}` | API 31/33/35/36 behaviour differences, app handling, evidence, capture-health binding per behaviour | `BehaviorMatrixContractTest` (levels, cited paths exist, rendered view equals the JSON) |
| `docs/platform/restricted-settings-matrix.md` | Play-installed, sideloaded and restored builds × sensitive settings × API level, with the supported QA recovery path | `RestrictedSettingsMatrixTest`, `RestrictedSettingsMatrixDocTest` (table block generated from code) |
| `docs/platform/sideloaded-qa-prerequisites.md` | Developer verification, install paths, device prerequisites | `scripts/qa_sideload_prerequisites.py` + `scripts/tests/test_qa_sideload_prerequisites.py` |
| `docs/platform/capture-health-identifiers.json` | Platform-capability and capture-health identifiers bound to the shared client state taxonomy (docs#1 v1.0.0) | `ClientStateTaxonomyTest` |

| Primitive | Purpose | Tests |
| --- | --- | --- |
| `PlatformBaseline` | The pinned levels (target 36, compile 36, min 26, QA levels 31/33/35/36, 600dp large-screen threshold) as code | `TargetConformanceTest` compares them with the catalogue and each variant's **merged** manifest |
| `platform.ui.RootSurface` | Mandatory root of every screen: applies `WindowInsets.safeDrawing` once, lays content out by `WindowWidthClass` (compact <600dp, medium 600–839dp, expanded ≥840dp with an 840dp content cap); tags `pennilogic.root_surface`, `pennilogic.root_inset_area`, `pennilogic.root_content` | `RootSurfaceTest` (injected insets, 360/700/1000dp), `MainActivityLayoutTest` (real activity at four window sizes, both variants), `ApiLevelMatrixTest` (real activity on the SDK 31/33/35/36 runtimes), `PlatformBaselineSourceTest` (every `setContent` root uses it; insets consumed nowhere else), `EdgeToEdgeInstrumentedTest`, `LargeScreenInstrumentedTest` (local) |
| `platform.ui.PenniLogicBackHandler` | The only way to intercept back: `PredictiveBackHandler` with gesture progress forwarded, cleared on cancel, `onBack` on commit; the manifest opts the application into predictive back and no legacy `onBackPressed()`/`KEYCODE_BACK` path exists | `PenniLogicBackHandlerTest`, `MainActivityLayoutTest` and `ApiLevelMatrixTest` (unhandled back finishes), `TargetConformanceTest`, `PlatformBaselineSourceTest`, `PredictiveBackInstrumentedTest` (local) |
| `platform.state.ClientState*` | Pin of the shared taxonomy: the eight states, causes, scopes, the three `T-AND-07` conditions, the seven platform-capability reasons and the `client_state.<id>` signal with exactly the published attributes | `ClientStateTaxonomyTest` |
| `platform.settings.RestrictedSettingsMatrix`, `CaptureSettingsProbe` | What each install source can enable per API level; classification of this build's install source from `getInstallSourceInfo`; the reason a capture surface renders when notification access is missing | `RestrictedSettingsMatrixTest`, `InstallSourceProbeTest` |

Conformance rules enforced on every build: the merged manifest of each variant targets API 36 and
declares no `maxSdkVersion`; no source-set manifest declares `<uses-sdk>`; `enableOnBackInvokedCallback`
is `true` on the application and `false` on no activity; no activity declares `screenOrientation`,
`resizeableActivity="false"`, `minAspectRatio` or `maxAspectRatio`; no `android.window.PROPERTY_COMPAT_*`
manifest property exists; no theme sets `windowOptOutEdgeToEdgeEnforcement`; no code calls
`setRequestedOrientation()`. The second pull request of android#57 adds the scheduling, capture-health
and Play Integrity primitives listed as `planned_pr2` in the behaviour matrix.

## Observability

- Process start logs one structured `Log.i` event with tag `PenniLogic`:
  `{"event":"app_start","build_type":…,"version_name":…,"version_code":…,"configuration":"loaded"|"invalid","problems":[…]}`.
  It contains build metadata and problem identifiers only; no configuration values, no user data.
- Pipeline metrics: build duration, unit test counts and lint issue counts per gate in
  `build/quality-metrics.json` and, in GitHub Actions, the job summary.

## Rollout and rollback

The scaffold ships no runtime feature flag and touches no user data. Integration is a normal
protected pull request into `main` (never a direct push). Rollback is a revert of the scaffold
commit; nothing outside this repository depends on it yet.

## Non-goals

Feature architecture, dependency injection, encrypted storage and navigation (android#2);
instrumented device journeys and the device lab; store distribution and release signing
material provisioning; feature UI, a change of the minimum API or any bypass of a platform
restriction (android#57 non-goals).
